# fssql 分阶段完善与 DuckDB 替换方案

## 1. 目标与已确定的边界

目标是完整承接当前项目的本地处理、抽样、脱敏、类型化导入及 CSV/Parquet 导出能力，补齐已确认的 P0/P1，最终使这些生产路径不再依赖 DuckDB。

采用以下已确认的路线：

- **允许调用方最小适配**：新增 fssql 适配器，保留业务接口、处理规则及请求协议；不要求复刻 DuckDB Appender、普通 CREATE TABLE/INSERT。
- **生产实现使用纯 Go**：保留自研 Vector/DataChunk、Push Pipeline、受管内存及 Controlled Parquet；允许少量 codec 依赖。
- **抽样保持业务确定性**：哈希抽样及具有完整排序键的确定性抽样与现有结果一致；原生随机抽样保证数量、概率及同种子复现，不要求选中与 DuckDB 相同的行。
- **首轮原生加密覆盖输出**：消费端继续透传。加密读取只通过外部参考读取器做互操作验证，不列为 fssql 首轮公共能力。
- **保留 Go 1.22 下限**：先实现 Snappy 页面压缩。Zstd 不作为本轮替换前置条件。
- **不扩大业务规则支持范围**：例如当前禁止 BLOB、UBIGINT 参与部分脱敏或稳定哈希的限制继续保留；支持保真传输不等于允许参与所有规则。

本次属于下一功能版本建设。新增 SQL、窗口和公共扩展入口应更新能力合同及 ADR，不混入既有版本的缺陷修复声明。

阶段关系如下：

| 阶段 | 主要交付 | 依赖 | 完成后的能力 |
|---|---|---|---|
| 0 | 兼容基线、验收语料、加密原型 | 无 | 固定替换范围，提前验证最大风险 |
| 1 | 本地 VFS、文本扫描回归 | 0 | 本地读取和原子 COPY 可用 |
| 2 | 类型及全链路保真 | 0 | 特殊类型不再发生隐式精度损失 |
| 3 | 类型化批次数据源、重扫支持 | 1、2 | 数据库行流不经 CSV 即可进入引擎 |
| 4 | 基础表达式、函数、UDF、CSV 参数 | 2、3 | 脱敏及简单抽样可执行 |
| 5 | 派生表、窗口、完整抽样 | 3、4 | 当前处理编译器的 SQL 全部可执行 |
| 6 | 导出 API、Snappy、原生加密 | 0 原型、1、2、4 | 输出格式和加密契约齐备 |
| 7 | 调用方迁移、大文件验收、发布 | 1—6 | 达到完整替换条件 |

阶段 6 可与阶段 5 交错推进；各阶段以验收结果结束，不以“代码已合并”作为完成标准。

## 2. 公共接口与数据流

新增接口全部位于现有公共包，不向外暴露 `internal` 类型。

| 接口 | 确定的职责 |
|---|---|
| `Config.LocalFiles *LocalFileConfig` | 显式开启本地文件能力，配置一个绝对根目录；零配置继续不开启 |
| `FileURI(path)` | 将绝对本地路径正确转换为 URI，统一 Windows 盘符、分隔符及字符转义 |
| `Config.TableFunctions []TableFunction` | 在 Open 时注册固定名称、固定 schema 的零参数表函数，满足当前类型化来源需求 |
| `BatchReader`、`BatchWriter` | 引擎提供受管批次缓冲，调用方按类型填充；支持 NULL、整数、浮点、精确 DECIMAL、文本、二进制和时间 |
| `Config.ScalarFunctions []ScalarFunction` | 注册参数类型、结果类型、NULL 策略、确定性属性及求值回调 |
| `Config.ParquetKeys` | 根据请求上下文、keyId 和算法解析密钥，不把密钥放入 SQL |
| `DB.CopyTo(ctx, query, destination, options)` | 返回实际输出行数、文件字节数及结果列信息；与 SQL COPY 共用执行和提交路径 |

接口行为固定如下：

- 表函数和 UDF 定义在 `Open` 时校验并冻结；首轮不提供查询期间动态修改注册表的能力。
- `BatchWriter` 提供类型化 setter 和显式 `SetNull`，不要求调用方构造内部 Vector。
- 批次行数不超过现有 `vector.DefaultVectorSize`；默认批次字节目标为 1 MiB。单个大字段允许独占批次，但必须先完成内存预留。
- 文本、二进制及 DECIMAL 数据在借用期内复制到引擎所有的缓冲，不能保留来源驱动即将复用的切片。
- 同一查询内，同一注册来源只打开一次；多处引用通过查询级物化结果重扫。
- `DESCRIBE` 和 schema 绑定不读取行流、不执行 UDF。
- UDF 默认按易变函数处理；只有显式声明确定性才能参与常量折叠等优化。HMAC 在请求密钥快照内声明为确定性。
- `CopyTo` 失败时不返回成功结果，不发布不完整文件；现有 `Exec` 签名保持不变。

最终主要数据流为：

```text
数据库 RowStream
  → 调用方类型适配器
  → 受管批次数据源
  → 查询级重扫物化（仅需要时）
  → 抽样 / 脱敏 / 投影
  → CSV 或 Parquet writer
  → 页面压缩 / 原生加密
  → VFS 原子提交
  → ExportResult
```

文件输入继续经过 FileSetPlanner、冻结扫描快照和现有格式读取器。

## 3. 分阶段实施内容与验收

### 阶段 0：固定兼容基线并提前验证加密

**实施内容**

1. 建立业务兼容矩阵，将每项需求关联到输入类型、生成 SQL、预期 schema、预期结果及资源预算。
2. 从现有抽样、脱敏编译器和类型化导出流程生成测试语料，覆盖文件来源和数据库行流来源。
3. 迁移基线固定为调用方当前 DuckDB 及自编译扩展版本；保留 fssql 原有 Stable 回归基线，两类报告分别记录版本，避免混用。
4. 重新核对 MEM-001、PERF-001、SQL-SAMPLE-001：区分已有实现、已有小规模测试和大文件验收状态。
5. 用现有加密扩展生成 AES-128、AES-256 样本，验证最小纯 Go 写出原型能够被原读取路径正确读取。

加密必须兼容当前扩展的 `PARE` 文件及 `masterKeyID` 元数据。现有测试明确检查这些内容，不能以“符合通用 Parquet 加密规范”代替项目互操作验收。[现有加密往返测试](D:/WORK_FILE/zwyb_file/edge-agent-go/internal/processing/duckdb/encrypted_table_integration_test.go:19)

**交付与验收**

- 输出版本固定的 SQL 语料、类型样本、加密样本及兼容矩阵。
- 不支持项明确标为待实现，不通过跳过测试宣称支持。
- 加密原型至少通过两种密钥长度的正确读取、错误密钥拒绝和元数据识别。
- 当前尚未找到自编译扩展源码；以现有二进制和读取器生成事实基线。若原型无法互操作，完整替换保持未完成，不能降级为其他加密格式。

### 阶段 1：补本地 VFS，并验收已有文本扫描修复

**实施内容**

- 增加本地驱动的 Stat、分页 List、精确范围读取、流式写入、删除和单文件原子发布。
- 本地路径限定在显式配置的根目录内；统一处理 Windows 盘符、Unicode、空格及 URI 转义。
- 写出使用目标同目录临时文件，完整关闭后发布。分别实现 Windows、Linux 的提交行为，不能直接假定两者的 rename 语义相同。
- 只声明平台实际支持的 capability；未实现的条件覆盖等操作在写入前拒绝。
- 本地文件读写继续经过 VFS、受管缓冲和既有 COPY 提交流程。
- 复用当前 CSV/NDJSON 串行窗口实现，补齐真实生产路径的大文件回归，不重写已经存在的扫描器。

**验收**

- 本地 CSV、NDJSON、Parquet 查询及 COPY 往返成功。
- 覆盖空文件、无匹配、跨块记录、CSV 引号内换行、CRLF、BOM、尾部无换行及超长记录。
- 输入发生可检测的身份变化时失败，不能跨文件版本拼接读取结果。
- 注入取消、短读、磁盘满和提交失败，检查原完整目标不被不完整产物覆盖。
- 以 64 MiB、默认 256 MiB 预算扫描大于预算的普通记录文本文件；成功后更新 MEM-001 证据。
- 大字段超过预算时明确失败并清理，不能绕过内存上限。

**阶段完成标志：**本地 I/O 可用，MEM-001 不再仅依赖过时登记判断。

### 阶段 2：补齐核心类型及全链路保真

**实施内容**

新增核心和公共类型：

- `BLOB`
- `UTINYINT / USMALLINT / UINTEGER / UBIGINT`
- `TIMESTAMP_NS`
- `TIMESTAMPTZ`，首轮保持调用方现有微秒精度上限

既有 `TIMESTAMP` 继续表示微秒日历时间；DECIMAL 保持最大 38 位，不扩大精度范围。

每种新增类型必须贯通：

- Vector、NULL validity、复制和批次访问；
- 实际会经过的投影、排序、连接及聚合载荷搬运；
- spill 序列化、重读和结果适配；
- CSV/Parquet 读写及类型元数据。

具体保真要求：

- 纳秒输入保持纳秒类型，不再隐式执行除以 1000。
- Parquet 时间单位和 `IsAdjustedToUTC` 与逻辑类型一致。
- 无符号整数按无符号语义读取、比较及写出。
- BLOB 使用二进制语义，不标注为 UTF-8 文本。
- DECIMAL 摄入和重标度不经过 `float64`；无法精确表示时拒绝。
- 原始时间点输出与用于处理规则的 UTC 日历投影分开，保留现有辅助列恢复行为。
- 显式 SQL CAST 的舍入、截断遵循参考语义；摄入和输出不得进行未声明的精度转换。

原生结果增加 `Uint64`、`Bytes` 等访问器。`database/sql` 中 UBIGINT 使用精确十进制文本，BLOB 使用字节值，时间结果保留对应精度。

**验收**

覆盖整数边界、超过 `MaxInt64` 的 UBIGINT、38 位 DECIMAL、负值、全 NULL 列、空 BLOB、含零字节 BLOB、纳秒尾数及不同时区表示的同一时间点。

所有样本都经过：

```text
输入 → Vector → spill → 重读 → 导出 → 外部读取
```

**阶段完成标志：**无处理规则的类型化数据可以保真通过全部必需路径。

### 阶段 3：提供类型化流式摄入与重扫支持

**实施内容**

- 实现前述公共表函数和批次接口。
- 在调用方增加 `RowStream → BatchWriter` 适配器，复用现有 schema 校验、字段限制及精确 DECIMAL 转换。
- 单次消费的查询直接流式执行。
- 同一来源被多个 CTE、JOIN 分支或统计分支引用时，物化一次并共享；达到预算后写入现有临时存储。
- 物化结果保存全部类型、NULL 和来源快照身份，不通过 CSV 落盘。
- 来源消费失败后立即停止，不继续读取、重开来源或静默改走另一条导入路径。
- 所有完成、失败、取消路径关闭来源并释放批次、物化结果和临时文件。

一次性来源只承诺当前查询生命周期内重扫，不承诺进程重启后重新获得原数据库游标；跨进程恢复仍由调用方现有任务和数据集机制负责。

**验收**

- 验证来源驱动复用字节缓冲后，已填充数据不发生变化。
- 多次引用读取同一快照，上游实际只消费一次。
- 内存物化与强制落盘结果一致。
- 预算耗尽、来源错误、消费者提前结束和取消后均无残留所有权。
- 空来源保留完整 schema，能够生成合法空输出。

**阶段完成标志：**`ExportTable` 的保真摄入可迁移，普通 CREATE TABLE/INSERT/Appender 不再是替换阻塞项。

### 阶段 4：补基础 SQL、标量函数、UDF 和 CSV 参数

**SQL 实施范围**

| 类别 | 本轮必须覆盖 |
|---|---|
| 表达式 | 显式 CAST、CASE、`||`、精确小数字面量、所需整数及 DECIMAL 运算 |
| 字符串 | `length`、`substr`、`strpos`、`replace`、`repeat`、`lower`、`hex` |
| 数值和条件 | `floor`、`mod`、`least`、`greatest`、`coalesce`、`nullif` |
| 哈希 | `md5` |
| 时间 | `strftime`、`strptime`、`date_trunc`、当前导出所需 UTC `timezone` 转换 |
| 随机 | 每行求值的 `random()` |

优先复用现有语义和执行器，缺失部分增加精确 kernel，不另建一套表达式执行系统。

关键语义包括：

- CASE 和 COALESCE 只对实际需要的行求值。
- Unicode 字符串长度和截取按字符处理。
- 日期格式逐项覆盖当前编译器输出，包括抽样规范化使用的毫秒格式。
- NULL、空串、空二进制严格区分。
- 函数的结果类型、DECIMAL 精度和 NULL 行为参与 Binder 校验。

**UDF 实施内容**

- 增加绑定到实际执行器的标量回调。
- 在新适配器中注册 `data_plane_hmac_sha256`，保持现有输入转换、UTF-8 字节及小写十六进制输出。
- 每次导出使用独立函数和密钥配置，禁止进程级可变密钥表。
- UDF 错误向查询传播并中止输出；密钥不进入日志、计划或恢复清单。

**CSV 实施内容**

支持 `HEADER`、`columns`、`auto_detect`、`allow_quoted_nulls`：

- `columns` 只接受静态列名和类型声明。
- `auto_detect=false` 必须提供 schema。
- 显式 schema 存在时，推断不能覆盖列类型。
- 绑定、运行时重绑和实际解码共用同组选项。
- 参数省略时维持既有行为；新调用方显式传入所需选项。
- 保留 quoted 状态，正确区分引号空串和 NULL。

**验收**

- 阶段 0 的全部脱敏语料通过。
- HMAC 已知向量、NULL、Unicode、密钥不存在及租户隔离通过。
- 表达式在 FLAT、CONSTANT、DICTIONARY 表示下结果一致。
- CSV 显式类型导入覆盖 DECIMAL、日期时间及全 NULL 列；二进制等特殊终态编码继续由类型化路径和输出适配控制。

**阶段完成标志：**脱敏、确定性哈希过滤及简单查询可运行。

### 阶段 5：补派生表、窗口和完整抽样

**关系与窗口实施内容**

- 支持 FROM 派生表、别名和结果列作用域。
- 支持当前整群抽样需要的 `IS NOT DISTINCT FROM`，贯通 NULL 安全连接。
- 多次引用 CTE 复用物化结果，避免重复消费来源或重复生成易变值。
- 支持当前生成 SQL 使用的窗口集合：
  - `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)`
  - `COUNT(*) OVER ()`
  - `SUM(...) OVER ()`
  - 显式 `ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING`
- 窗口排序和物化复用外部排序、spill 与内存管理。
- 未纳入本轮的窗口函数和 frame 明确拒绝，不接受后产生近似结果。

**抽样实施内容**

- Reservoir 使用专门的蓄水池算子，空间与样本规模相关，避免全量随机排序。
- Bernoulli 逐行独立决定是否入样；重复业务键和重复整行不能被绑定为同一个事件。
- 支持当前 `USING SAMPLE reservoir(...)`、`bernoulli(...)` 及 `REPEATABLE` 形式。
- 带种子的原生抽样首轮使用稳定的串行来源顺序，避免 worker 调度改变结果。
- 系统、分层和整群抽样继续执行既有 SQL 算法，不重新定义业务配额规则。
- 哈希规范化保持现有类型标记、长度前缀、NULL 标记、日期格式及摘要大小写。

**验收**

- 覆盖全部现有抽样方法及其与脱敏的组合。
- 覆盖零行、样本大于总体、比例 0/1、显式 seed=0、NULL 键、重复行、极小分层和层容量不足。
- 确定性场景在完整排序条件下与参考结果逐行一致；无整体排序承诺时比较多重集合。
- 原生随机场景验证样本数量、同种子复现及统计性质，不比较 DuckDB 的具体入样成员。
- 单 worker、多 worker、内存执行与强制 spill 的确定性结果一致。

**阶段完成标志：**当前处理编译器的业务语料全部可执行。

### 阶段 6：完善导出、Snappy 和原生加密

**导出接口**

- 实现 `CopyTo`，与现有 COPY 共用 Binder、格式 writer、VFS 和提交逻辑。
- 输出行数在最终 sink 统计，替代调用方对 DuckDB COPY 返回行数的依赖。
- 输出 schema 来自实际绑定结果，替代为获取元数据而再次执行来源查询。
- 保留 CSV 的字段顺序、表头、强制引用、NULL/空串区分、BLOB 十六进制文本及 UTC 时间点文本约定。

**Snappy 页面压缩**

- 使用 `github.com/golang/snappy v1.0.0` 的 block 编码接口。
- 先按最大编码长度预留目标缓冲，禁止依赖内部扩容分配大块非受管内存。[编码接口](https://github.com/golang/snappy/blob/master/encode.go)
- 更新页面尺寸、列块压缩尺寸、codec 和 offset；禁止对整个 Parquet 文件套压缩流。
- fssql 既有默认压缩行为保持不变；新业务适配器显式选择 Snappy。
- 本轮不改写 CSV/NDJSON 的其他压缩实现。

**原生加密**

- 将阶段 0 验证过的写出子集接入 Controlled Parquet。
- 保持 AES-128/256、加密 footer、当前 key metadata 和 keyId 契约。
- 密码原语使用 Go 标准库；模块组织、AAD 和元数据遵循实际兼容格式。[Parquet 模块加密规范](https://parquet.apache.org/docs/file-format/data-pages/encryption/)
- 压缩后再加密；各模块生成独立 nonce，重试整文件时重新生成。
- 执行前校验算法、密钥长度和 keyId；密钥解析失败时不打开输出。
- 清单记录格式、codec、算法和 keyId，不记录密钥材料；相关选项参与导出身份校验。
- 失败或恢复按未完成文件整体重写，不追加不完整加密页面。

**验收**

- 无压缩、Snappy 文件均能被外部读取器读取。
- AES-128/256 文件由现有自编译扩展成功读取，恢复精确类型和值。
- 无密钥、错误密钥及篡改样本读取失败。
- 压缩与加密组合通过，不检查随机密文逐字节相等。
- 写入、footer、关闭及提交任一步失败，均不发布不完整最终文件。

**阶段完成标志：**全部 P0 功能齐备，Parquet 未压缩写出这一 P1 得到解决。

### 阶段 7：迁移调用方并完成替换验收

**调用方改造**

- 新增 fssql Exporter，继续实现现有导出接口。
- 数据库来源走类型化批次入口；文件来源走本地 VFS。
- 保留现有处理计划、规则顺序、字段限制、分段逻辑及加密请求协议。
- 每次导出使用独立 DB 配置，绑定来源、UDF 和密钥解析器。
- 将 `read_csv_auto`、特定 JSON 读取形式等少量来源 SQL 改为 fssql 已支持的显式形式。
- 使用现有 `CREATE VIEW` 或直接关系，去掉仅用于 DuckDB 导入的建表、Appender 和连接设置。
- 使用 `CopyTo` 的结果构造行数、字节数和列信息。
- 保留现有约 256 MiB **逻辑输入段**边界，不改解释为物理文件大小上限。

迁移期间通过显式引擎开关选择实现；单次任务固定一个引擎。失败后不能自动重新消费数据库来源并切换引擎。

**MEM-001 验收**

- 重跑原有大文本样本，并覆盖 256 MiB、512 MiB、1 GiB 级普通记录文件。
- 分别测试 64 MiB、默认 256 MiB 引擎预算。
- 区分扫描、物化、排序和输出的峰值，不把所有操作都宣称为固定内存流式执行。
- 物化超过临时存储预算时验证明确失败和完整清理。

**PERF-001 验收**

构造具有明确列块和行组布局的固定样本，直接统计物理 I/O：

| 场景 | 必须满足的结果 |
|---|---|
| 单列投影 | 不读取无关列的数据页 |
| 统计信息确定不匹配的过滤 | 对应行组不读取数据页 |
| 只匹配一个行组 | 仅扫描匹配组所需列 |
| 安全的 LIMIT 100 | 达到条件后停止，读取量仅包含必要页面和有界预读 |
| 不支持的复杂谓词 | 保留 residual filter，结果正确且不错误裁剪 |
| 嵌套投影 | 如仍走完整读取，限制必须显式记录 |

实测通过后才能关闭缺陷，不能只依据 optimizer 计划或返回行数判断。

## 4. 统一发布门槛与后续范围

每个阶段交付一次验收报告，记录代码版本、工具版本、样本标识、通过项、未支持项、资源测量和失败清理结果；复用现有测试设施，不另建重复框架。

完整替换必须同时满足：

1. **业务覆盖**：阶段 0 矩阵全部通过，最终发布任务中没有跳过的必需能力。
2. **类型正确**：特殊类型摄入、spill、处理和输出无隐式精度损失。
3. **语义正确**：确定性处理与参考结果一致；随机处理达到已确认的兼容等级。
4. **格式互操作**：普通及加密 Parquet 被实际下游读取路径接受。
5. **资源受控**：受管内存和临时存储不突破配置上限；同时报告 Go heap、RSS、GC、临时磁盘峰值和实际网络字节数。
6. **失败完整性**：取消、预算耗尽、来源错误、磁盘满、写入和提交失败后，任务、请求、句柄、reservation 和临时所有权均释放。
7. **跨平台**：Windows、Linux 的相关单元与集成测试通过；Race 测试在支持的平台执行，交付构建使用 `CGO_ENABLED=0`。
8. **性能可评估**：公布与 DuckDB 的吞吐、首批延迟、总耗时及产物大小对比；正确性、资源上限和物理裁剪作为硬门槛，不虚设尚未约定的同速要求。
9. **迁移可回退**：发布期间保留任务级引擎选择，达到全部门槛后设为 fssql 默认；完成必要观察后再移除这些路径中的 DuckDB 依赖。

本轮明确不建设普通持久表、完整 DML、事务、DuckDB Appender 仿真、通用插件 ABI、递归查询或完整窗口函数体系。公共自定义 VFS 注册、Zstd、Parquet 字典写出和更细粒度裁剪作为后续独立增量，不阻塞已满足业务要求的完整替换。

最终交付判定是：**当前项目的必需处理路径全部通过 fssql 执行和互操作验收，且所有限制均有明确边界；不能以各阶段功能分别可用替代端到端完成。**
